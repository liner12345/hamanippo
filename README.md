# 配送日報

配送先を回った順にタップして記録し、LINEに貼れる日報テキストを作るツール。
ビルド不要の静的サイトなので、そのままGitHub Pagesに置けば動きます。

出力例：

```
2026/8/1(土)

〇〇商事 豊田倉庫
△△工業（□□運輸 浜松DC）
□□運輸 浜松DC
××製作所
```

括弧は転送。「△△工業で引き取って、□□運輸 浜松DCへ持っていった」という意味です。

---

## 1. GitHub Pagesに置く

1. GitHubで新しいリポジトリを作る（例：`nippou`）。Publicにする
2. このフォルダの中身を全部そのリポジトリのルートに置いてpush
3. リポジトリの **Settings → Pages** を開く
4. Source を **Deploy from a branch**、Branch を **main / (root)** にして Save
5. 1〜2分で `https://<ユーザー名>.github.io/nippou/` が開くようになる

パスはすべて相対指定なので、サブディレクトリでもそのまま動きます。

## 2. iPhoneに入れる

Safariで開く → 共有ボタン → **ホーム画面に追加**。

ホーム画面から起動するとアドレスバーが消えて全画面になり、圏外でも開けます。
**追加しておくと保存データも消えにくくなる**ので、これはやっておいてください（後述）。

## 3. 使い方

### 日報タブ

- 下の **＋ 配送先を追加** で一覧から選ぶ。タップした順に並びます
- 各行の **⋮** から、メモ追加・並べ替え・削除ができます
- **出力** を押すとプレビューが出ます。そこから3通り
  - **共有する** … iPhoneの共有シートが開きます。LINEを選んで送信先を選ぶだけ
  - **LINEで直接送る** … 共有シートを飛ばしてLINEの送信先選択画面へ
  - **テキストをコピー** … 他のアプリに貼りたいとき

### コース（一括呼び出し）

いつも同じ順番で回る配送先は「コース」に登録しておけます。

日報タブの上に並ぶ **定期配送** のようなボタンを押すと、登録した配送先がその順番で一気に並びます。日付は今日の日付が自動で入っています。

- 作り方：**コースを作る** → 名前を付けて、回る順に配送先をタップ → 保存
- コース名は自由に変えられます（「定期配送」「月曜ルート」など）
- 順番の入れ替えは編集画面の ↑ ↓ で
- 押し間違えたら、追加直後に出る **取り消す** で戻せます
- **ルートのURL**（任意）… Googleマップで組んだルートの共有URLを貼っておくと、コースのボタンの右に地図アイコンが出ます。押すとそのルートが地図アプリで開きます。`https://` で始まるURLだけ登録できます
- 追加は上書きではなく末尾に足す動きなので、コースを押したあとに単発の配送先を足したり、コースを2つ重ねたりもできます

### ページ（1日に2便以上走ったとき）

**1日はページに分かれます。** 午前と午後で2回走ったなら、8/2 のページ1に午前、ページ2に午後を入れます。

日付の下のバーがページの切り替えです。

- **＋ ページ** … 新しいページを作って、そこへ移ります
- **ページ名をタップ** … そのページへ切り替え
- **選択中のページの ⋮** … 名前の変更・並べ替え・削除

**選択中のページの ⋮ → このページを複製** で、同じ配送先を並べたページがすぐ右にできます。午前と同じ先を午後も回るときや、昨日と同じルートを走るときに、コースを作らなくても1タップで済みます。転送の記録もそのまま複製されます。

別のページを消したいときは、いったんそのページへ切り替えてから ⋮ を押します。ページが1枚だけのときは削除できません（日付ごと消したい場合は「クリア」を使ってください）。

ページは**完全に独立**しています。出力・クリア・転送はすべて、いま選んでいるページの中だけで動きます。午前の日報を出して送り、ページ2へ切り替えてもう一度出力する、という使い方になります。

```
（ページ1を出力）        （ページ2を出力）
2026/8/2(日) 午前        2026/8/2(日) 午後

〇〇商事 豊田倉庫         □□運輸 浜松DC
△△工業 浜松工場          ××製作所
```

空で名前の無いページにコースを入れると、**コース名がそのままページ名になります。** 「午前ルート」を押せばページ名が「午前ルート」に。名前は後から自由に変えられますし、空にすれば「ページ1」「ページ2」の表示に戻ります。

出力にページ名を出すかどうかは設定で選べます（日付と同じ行 / 次の行 / 出さない）。

### 転送を記録する

「A社で頼まれて、その荷物をB社に持っていった」場合。

**A社をこれから追加するとき**（電話で呼ばれて寄った場合など）
配送先を選ぶ画面で、A社の行の右にある **転送** ボタンを押す → 続けて届け先（B社）を選ぶ。
A社とB社が2行まとめて入ります。

**A社をすでに追加済みのとき**
A社の行の **⋮** → **ここで転送を頼まれた** → 届け先（B社）を選ぶ。

どちらでも結果は同じで、テキストにはこう出ます。

```
A社（B社）
B社
```

同じ場所で2件引き取ったときは `A社（B社・C社）` とまとまります。
書き方は設定で4通りから選べます（`（→B社）` / `B社 ※A社より転送` / 注記なし）。

### 配送先タブ

配送先の登録・編集・カテゴリ分け。行の右の **＋ 追加** ボタンを押すと、その場で日報に追加できます。追加先は日報タブでいま選んでいる日付とページです（履歴から過去の日を開いたあとは、その日に入ります）。追加したときに出るトーストに日付が出るので、そこで確かめられます。

カテゴリは**配送先が増えたときに探しやすくするためだけのもの**で、日報のテキストには一切出ません。地域でも取引先区分でも、自分が探しやすい分け方にしてください。

### 履歴タブ

過去の日付をタップすると、その日の日報を開いて編集・再出力できます。

履歴は月ごとに区切られています。月の見出しの右にある **まとめて出力** を押すと、その月の記録が1つのテキストになります。

- **詳細** … 日付ごとに、その日回った配送先を全部並べます。1日に2ページ以上あるときは、ページ（午前・午後など）も見出しとして出ます
- **要約** … 日付ごとに1行だけ（件数とページの内訳）。最後に「よく行った先」と「コース別」の集計が付きます

上の **詳細 / 要約** で切り替えます。文字数が上に出るので、送る前の目安にしてください。

**LINEへ直接送るときは「要約」を使ってください。** 詳細は長すぎて送信に失敗することがあります。詳細を送りたいときは **共有する** から送ってください。

月のまとめには、日報の設定のうち **転送の書き方** だけが反映されます。「日付より前に入れる文字」「行番号」「最後に入れる文字」は日報1通のための設定なので入りません。

## 4. 設定でできること

| 項目 | 内容 |
|---|---|
| 日付より前に入れる文字 | `【日報】` など。**改行できます**（社名や氏名を2行目に置けます）。空なら日付から始まります |
| 日付の書き方 | `2026/8/1(土)` `2026.08.01(土)` `2026年8月1日(土)` `8/1(土)` |
| 転送の書き方 | `A（B）` / `A（→B）` / `B ※Aより転送` / 注記なし |
| ページ名の出し方 | `2026/8/1(土) 午前` / 次の行に出す / 出さない |
| 行番号 | `1. 〇〇商事` の形式にする |
| 最後に入れる文字 | 締めの一文など。**改行できます** |

### 差し込みタグ

「日付より前に入れる文字」「最後に入れる文字」の中に次の文字を書くと、出力するときにその日の内容へ置き換わります。

| タグ | 置き換わる内容 |
|---|---|
| `{カテゴリ}` | そのページに出てくる配送先のカテゴリ。複数あれば `・` でつなげます |
| `{ページ}` | ページ名（名前が無ければ「ページ1」など） |
| `{日付}` | 設定した書式の日付 |
| `{件数}` | そのページの配送先の数 |

例：「日付より前に入れる文字」に `【日報】{カテゴリ}` と書いておくと

```
【日報】サンモリッツ・ホール
2026/8/2(日) 午前便

サンモリッツ太閤
サンモリッツ今池
市民会館
```

カテゴリは**そのページに実際に含まれている分だけ**が、route に出てくる順で並びます。ページごとに中身が違えば、出るカテゴリも変わります。

**タグだけを書いた行は、中身が空のときは行ごと消えます。** 例えば `{カテゴリ}` だけの行は、配送先が0件のときは空行にならず消えます。もともと何も書いていない空行はそのまま残ります。存在しないタグ（`{あああ}` など）は置き換えずそのまま出力されます。

## 5. データの保存について

**保存先は端末のブラウザ内（localStorage）だけです。** サーバーには何も送りません。

そのため次の点に注意してください。

- **Safariの履歴・サイトデータを消すと、日報も配送先も消えます**
- ホーム画面に追加せずSafariのタブで使い続けると、iOSの仕様で数週間触らなかった場合にデータが破棄されることがあります。ホーム画面に追加して使えばこれを避けられます
- 機種変更やブラウザ変更でデータは引き継がれません

設定の **バックアップを書き出す** でJSONファイルとして保存できます。月に一度くらい書き出してiCloudドライブなどに置いておくと安全です。読み込みは **バックアップを読み込む** から。

記録が20件を超えてから30日以上書き出していないと、アプリを開いたときに **書き出しませんか** と一度だけ出ます。そのまま **書き出す** を押せば保存できます。促すのは7日に1回までで、書き出せば止まります。設定画面には最後に書き出した日付が出ます。

## 6. ファイル構成

```
index.html            画面の構造
styles.css            見た目
app.js                ロジック（データ管理・テキスト生成）
sw.js                 オフライン動作用
manifest.webmanifest  ホーム画面追加用
icon.svg / icon-*.png アイコン
```

データ構造は `app.js` の `freshDB()` を見れば全部わかります。

```js
{
  categories:   [{ id, name }],
  destinations: [{ id, name, catId, address, memo, uses, archived }],
  courses:      [{ id, name, items: [destId, ...] }],
  reports:      { "2026-08-01": { pages: [ { id, name, stops: [...] } ] } },
  // stops[] の各行: { id, destId, from, note, src }
  settings:     { header, dateStyle, transferStyle, pageName, number, footer }
}
```

`stops[].from` には、**品物を引き取った行のID**が入ります（配送先IDではありません）。
`null` なら通常の配送、IDが入っていれば「その行で引き取った品物の届け先」です。
この向きなので、括弧の注記は引き取った側の行に付きます。

`stops[].src` には、その行を入れたコースのIDが入ります（手で足した行には入りません）。現時点では記録のみで、表示や出力には使っていません。

1日は必ず1ページ以上を持ちます。ページをまたぐ参照は存在しないので、転送の紐付け（`from`）も必ず同じページ内で完結します。

出力テキストの形を変えたいときは `app.js` の `lineFor()` と `buildText()` だけ触れば済みます。

旧版のデータからの移行は `migrate()` にまとまっています。起動時とバックアップ読み込み時の両方から呼ばれるので、移行処理を足すときはここに書けば両経路に効きます。
